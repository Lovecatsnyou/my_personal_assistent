# Personal Assistant Bot

Персональный Telegram-ассистент: пользователи, задачи, заметки и напоминания в SQLite. Стек: Python 3.14, python-telegram-bot 22.8–22.x, Linux.

## Возможности

- Сохранено главное меню `/start` и справка `/help`.
- Пользователь автоматически регистрируется при первом обращении в личном чате;
  имя, фамилия и username обновляются без потери его задач.
- Создание, просмотр, выполнение и удаление задач через команды и кнопки.
- Удаление только после подтверждения. `/cancel` отменяет ввод и делает старое
  подтверждение недействительным. Новый выбор действия также отменяет предыдущий.
- Постраничный список по 5 задач, новые сверху; выполненные остаются в списке с ✅.
- Название задачи — от 1 до 300 символов. Неверные ID, повторные нажатия,
  устаревшие кнопки и ошибки хранилища обрабатываются сообщением пользователю.
- Каждая операция ограничена Telegram ID владельца, SQL-запросы параметризованы.
  Управление задачами доступно только в личном чате с ботом.
- Заметки: создание (заголовок, затем текст), постраничный просмотр, поиск по
  заголовкам и тексту без учёта регистра (включая кириллицу, «ё» = «е»),
  редактирование заголовка или текста, удаление с подтверждением.
- Заголовок заметки — до 200 символов, текст — до 4000, запрос поиска — до 200.
  Показываются даты создания и последнего изменения.
- Напоминания: однократные и повторяющиеся (каждый день, неделю, месяц, час или
  по выбранным дням недели), личный часовой пояс, отключение и включение,
  редактирование и удаление с подтверждением. Отправку выполняет `JobQueue`.
- Погода (Open-Meteo): текущая погода и прогноз на 7 дней, поиск города на русском
  с выбором среди одноимённых мест, сохранённый основной город, кэш и показ последних
  сохранённых данных с пометкой при недоступности сервиса. Подробнее — раздел «Погода».

Кнопка «📰 Новости» сохранена как заготовка. Новости и AI пока не реализованы.

## Запуск в Arch Linux / Fish

Если Python ещё не установлен: `sudo pacman -S python python-pip`.
Проверьте `python --version` — проект проверен на Python 3.14.

```fish
cd /home/lovecatsnyou/Projects/personal_assistant_bot
python -m venv .venv
source .venv/bin/activate.fish
python -m pip install -r requirements.txt
```

`requirements.txt` содержит `python-telegram-bot[job-queue]>=22.8,<23.0`: extra
`job-queue` ставит APScheduler, без которого напоминания не работают (бот сообщит
об этом при запуске). Если окружение уже было создано для прошлой версии, выполните
`python -m pip install -r requirements.txt` ещё раз — установленная PTB 22.8
сохранится, добавятся только `apscheduler` и `tzlocal`.
Модуль погоды использует `httpx>=0.27,<0.29` — его уже ставит python-telegram-bot,
в `requirements.txt` он указан явно; новых пакетов для погоды устанавливать не нужно.

Одновременно должен работать **только один** экземпляр бота: при запуске он берёт
блокировку `assistant.lock`, второй экземпляр завершится с сообщением. Перед
обновлением остановите старый процесс (Ctrl+C или `pkill -f "python main.py"`).

При уже установленном окружении достаточно активации. Существующий `BOT_TOKEN`
используется без изменения. Если после переустановки ОС переменная отсутствует,
введите **прежний токен** без сохранения его в истории Fish:

```fish
read --silent --prompt-str 'BOT_TOKEN: ' BOT_TOKEN
set -gx BOT_TOKEN "$BOT_TOKEN"
python main.py
```

Токен получается у [BotFather](https://t.me/BotFather). Код читает только переменную
окружения `BOT_TOKEN`; `.env` автоматически не загружается. Не помещайте токен в код
или Git. Для остановки нажмите Ctrl+C. Если `BOT_TOKEN` уже задан, команды `read`
и `set` не нужны.

В Bash/Zsh активация: `source .venv/bin/activate`; безопасный ввод токена в Bash:
`read -rs -p 'BOT_TOKEN: ' BOT_TOKEN`, затем `export BOT_TOKEN` и `python main.py`.

Нажмите «📋 Задачи», чтобы открыть меню создания, просмотра, выполнения и удаления.
ID берётся из списка (`#12`), нумерация общая для БД; пропуски в номерах нормальны.
Текст без команды сохраняется только после `/add` или кнопки создания. Кнопки
главного меню и `/start`, `/help` завершают ввод. Чтобы использовать название,
совпадающее с кнопкой меню или начинающееся с `/`, передайте его после `/add`.

После перезапуска пользователи и задачи остаются в SQLite; незавершённый ввод и
подтверждения удаления сбрасываются. Старые подтверждения больше не действуют.

### Меню заметок

Кнопка «📝 Заметки» открывает меню: «➕ Добавить заметку», «📋 Мои заметки»,
«🔎 Поиск», «✏️ Редактировать», «🗑 Удалить», «🏠 Главное меню». В списке по 5
заметок, новые сверху: номер, заголовок, начало текста и даты. Кнопка заметки
открывает карточку с полным текстом и кнопками «✏️ Заголовок», «✏️ Текст»,
«🗑 Удалить», «⬅️ К списку». Длинная заметка, не помещающаяся в одно сообщение
Telegram (4096 символов UTF-16), отправляется несколькими сообщениями.

На каждом шаге диалога работают `/cancel` и кнопка «✖️ Отмена». Неверный ввод
(пустой, слишком длинный) не сбрасывает шаг: бот просит повторить. Пробелы и
переносы строк в заголовке схлопываются в один пробел, в тексте сохраняются.
Кнопки удалённой заметки, старые подтверждения и результаты поиска после
перезапуска бота обрабатываются сообщением, а не ошибкой. Даты хранятся в UTC,
показываются в часовом поясе компьютера, на котором запущен бот.

Задачи, заметки и напоминания не мешают друг другу: команда или кнопка одного
раздела, как и кнопки главного меню, отменяет незавершённый ввод и подтверждение
в другом. `/cancel` отменяет диалог того раздела, который сейчас активен.

### Напоминания

Кнопка «⏰ Напоминания» открывает меню: «➕ Создать напоминание», «📋 Мои
напоминания», «🔁 Повторяющиеся», «✏️ Редактировать», «🗑 Удалить», «🌍 Часовой
пояс», «🏠 Главное меню».

**Создание.** Текст (1–500 символов) → дата (кнопки «Сегодня/Завтра/Послезавтра»
или ввод `ДД.ММ.ГГГГ`, `ДД.ММ`, `ГГГГ-ММ-ДД`, «завтра») → время `ЧЧ:ММ` (24 ч) →
повторение → сводка → «✅ Создать». Новое напоминание должно начинаться в будущем.
Неверный ввод объясняется, и повторяется только текущий шаг. На любом шаге работают
`/cancel` и «✖️ Отмена». Кнопки шагов привязаны к конкретному диалогу: кнопки
завершённого или отменённого диалога не срабатывают.

**Повторения.**

| Вариант | Правило |
| --- | --- |
| Без повторения | Один раз; после успешной отправки — статус «выполнено» ✅ |
| Каждый день | В то же местное время |
| Каждую неделю | В день недели выбранной даты (сохраняется в `repeat_days`) |
| Каждый месяц | В число выбранной даты; если такого числа нет (31-е, 30-е, 29.02) — в последний день месяца, затем снова в исходное число |
| По дням недели | В выбранный набор дней (хранится как `0,2,4`, где 0 — понедельник) |
| Каждый час | Каждые 60 минут реального времени от первого момента, минута сохраняется |

Повторяющееся напоминание после отправки сразу получает следующий будущий момент.

**Часовые пояса.** У каждого пользователя свой пояс в таблице `user_settings`
(IANA-название: `Europe/Moscow`, `Europe/Warsaw`, `Europe/Berlin`, `UTC` и т. п.;
регистр не важен). Пояс не определяется автоматически: при первом `/remind` бот
предложит его выбрать. Моменты отправки хранятся в UTC, показываются в местном
времени.

- Переход на летнее время: время, которого нет (например, 02:30 в Берлине в ночь
  перевода часов вперёд), при вводе отклоняется — бот просит выбрать другое время.
  Если такая дата выпадет у ежедневного или еженедельного напоминания позже, оно
  сработает сразу после перевода часов (02:30 → 03:30).
- Переход на зимнее время: время, которое наступает дважды, бот предлагает выбрать
  кнопками («Первое (UTC+02:00)» / «Второе (UTC+01:00)»). Выбор сохраняется
  (`fold`) и используется для будущих повторений.
- Ежечасные напоминания считают реальные часы, поэтому в ночь перевода местное
  время срабатывания сдвигается вместе с часами, но интервал остаётся 60 минут.

**Смена часового пояса** (`/timezone`) действует на новые напоминания. Уже
созданные сохраняют собственный пояс (`reminders.timezone`) и срабатывают в тот же
момент, что и раньше; бот сообщает, сколько их. В списке и карточке у таких
напоминаний пояс указан в скобках, а новая дата или время при редактировании
вводятся в поясе самого напоминания. Чтобы перевести напоминание в новый пояс,
создайте его заново.

**Редактирование.** В карточке: «✏️ Текст», «📅 Дата», «🕒 Время», «🔁 Повторение»,
«⏸ Отключить» / «▶️ Включить», «🗑 Удалить» (с подтверждением). Изменение даты,
времени или повторения у выполненного или недоставленного напоминания снова его
включает; отключённое остаётся отключённым. Однократное напоминание с прошедшим
временем нельзя включить, пока не изменены дата или время. Изменение сохраняется,
только если напоминание не менялось с начала редактирования (поле `version`);
иначе бот сообщает, что изменение не применено.

### Отправка и восстановление расписания

- При запуске бот инициализирует SQLite, читает активные напоминания и ставит по
  одному заданию `JobQueue` на каждое (имя `reminder:<id>`; повторная постановка
  заменяет задание, дубликатов в одном процессе нет).
- Однократное напоминание, пропущенное, пока бот был выключен, отправляется один
  раз сразу после запуска. Повторяющееся пропускает прошедшие срабатывания и
  переносится на ближайший будущий момент — пачки старых уведомлений не будет.
- Временные ошибки сети/Telegram: до 3 повторов через 30 с, 2 мин и 10 мин
  (с учётом `RetryAfter`). Если повторы исчерпаны, однократное напоминание получает
  статус «не доставлено» ⚠️, повторяющееся переходит к следующему моменту.
- Окончательные ошибки (бот заблокирован пользователем, чат не найден) сразу
  переводят напоминание в статус «не доставлено» без повторов. После разблокировки
  его можно включить в карточке.
- Задание при срабатывании сверяет `version` и статус в SQLite. Удалённое,
  отключённое или изменённое напоминание старым заданием не отправляется.
- В журнал пишутся только номер напоминания и тип ошибки, не текст.

## Погода

Раздел «🌤 Погода» показывает текущую погоду и прогноз на 7 дней по данным
[Open-Meteo](https://open-meteo.com/en/docs). Используется бесплатный вариант API без
ключа (некоммерческое учебное использование в рамках условий сервиса). Сторонние
погодные сайты не парсятся, местоположение по IP не определяется.

| Команда | Действие |
| --- | --- |
| `/weather` | Текущая погода в основном городе; если он не выбран, бот спросит название |
| `/weather Казань` | Найти место и показать погоду, **не меняя** основной город |
| `/forecast` | Прогноз на 7 дней для основного города |
| `/forecast Казань` | Прогноз для указанного места |
| `/setcity Казань` | Найти место и сохранить его как основной город; без аргумента бот спросит название |
| `/mycity` | Сохранённый город: регион, страна, координаты, часовой пояс |
| `/cancel` | Отменить ввод названия города |

Меню «🌤 Погода»: «🌡 Текущая погода», «📅 Прогноз на 7 дней», «🔎 Найти город»,
«📍 Мой город», «🔄 Обновить прогноз», «🏠 Главное меню». Под результатом есть кнопки
«🔄 Обновить», переключение «погода ↔ прогноз» и, для места не из настроек,
«📍 Сделать моим городом».

**Выбор города.** Поиск идёт через Open-Meteo Geocoding API (`language=ru`): можно
писать по-русски и латиницей, находятся города разных стран. Название — от 2 до 100
символов. Если найдено одно место, оно выбирается сразу; если несколько (например,
«Париж» во Франции и в Техасе), бот покажет список «название, регион, страна,
координаты» и кнопки выбора. Сохраняются официальное название, регион, страна,
координаты, часовой пояс и ID геокодера. Основной город меняется только явно:
через `/setcity`, «Сменить город» или «📍 Сделать моим городом».

**Текущая погода**: температура и ощущаемая температура (°C), влажность (%), ветер
(км/ч, в скобках — примерно в м/с) и его направление, описание по коду WMO с эмодзи,
осадки (мм), местное время наблюдения. Подписи единиц берутся из ответа API
(`current_units`/`daily_units`); значения, которых нет в ответе, не показываются.

**Прогноз**: для каждого из 7 дней — «Сегодня/Завтра» или день недели, дата, описание,
мин./макс. температура, вероятность и количество осадков. Даты считаются по часовому
поясу выбранного места (`timezone` в запросе к Open-Meteo), а не компьютера. Сообщение
укладывается в лимит Telegram 4096 символов.

**Часовые пояса погоды и напоминаний независимы.** Пояс города хранится в
`user_locations`, пояс напоминаний — в `user_settings` (`/timezone`). Смена города не
меняет напоминания, и наоборот.

### Сеть, ошибки и кэш

Open-Meteo должен быть доступен **с компьютера или сервера, где запущен бот**.
Бот не включает VPN и не меняет маршрутизацию, DNS или прокси. Если на компьютере
Open-Meteo доступен только через VPN (например, Happ), включите его до запуска
бота. Если VPN работает как HTTP-прокси, а не через системный туннель, можно задать
переменную `HTTPS_PROXY` — httpx её учитывает. SOCKS-прокси требует пакета `socksio`
(`pip install "httpx[socks]"` в `.venv`), по умолчанию не установлен. Проверка доступности
из Fish:

```fish
curl -sS -m 10 'https://api.open-meteo.com/v1/forecast?latitude=55.75&longitude=37.62&current=temperature_2m' ; echo
```

- Один общий `httpx.AsyncClient` на всё время работы, закрывается при остановке бота.
- Таймауты: соединение 4 с, чтение 8 с, вся операция с повторами — не более 15 с.
- До 2 повторов с паузой 1 и 2 с при DNS-ошибке, обрыве соединения, ConnectTimeout,
  ReadTimeout, HTTP 429 и 5xx. HTTP 429 с `Retry-After` больше 5 с не ждём. HTTP 4xx и
  некорректный JSON не повторяются. Бесконечных повторов нет.
- Запросы выполняются фоновой задачей: бот сразу отвечает «⏳ Запрашиваю данные…»,
  затем заменяет это сообщение результатом. Пока Open-Meteo не отвечает, задачи,
  заметки и напоминания продолжают работать.
- Одновременные одинаковые запросы объединяются в один HTTP-вызов.

Кэш успешных ответов хранится в памяти процесса. Ключ — тип запроса и все параметры
Open-Meteo (координаты, часовой пояс, поля, единицы, число дней).

| Данные | Свежие (TTL) | Если Open-Meteo недоступен |
| --- | --- | --- |
| Текущая погода | 10 мин | показываются сохранённые данные не старше 1 часа |
| Прогноз | 30 мин | не старше 6 часов; прошедшие дни скрываются |
| Поиск города | 24 часа | — |

Устаревшие данные явно помечаются: «⚠️ Open-Meteo сейчас недоступен… Показаны
последние сохранённые данные, полученные 16.10 14:05, 35 мин назад. Это не текущие
данные». Если подходящих данных нет, бот сообщает о временной недоступности, причине
(DNS, таймаут, нет соединения, HTTP 429, ошибка сервиса) и предлагает «🔄 Повторить».
Кнопка «🔄 Обновить» запрашивает свежие данные, но не чаще раза в минуту для одного
места. В журнал пишутся только тип запроса и тип ошибки, без названия города.

### Ручная проверка погоды в Telegram

1. Остановите старый процесс, при необходимости включите VPN, запустите `python main.py`.
2. «🌤 Погода» → «🔎 Найти город» → `Москва`: должна прийти погода с кнопками.
3. «📍 Сделать моим городом», затем `/mycity` — город, регион, страна, пояс.
4. `/forecast` — 7 дней, первый день «Сегодня».
5. `/weather Париж` — список из нескольких мест; выберите «Техас, США». `/mycity`
   по-прежнему показывает прежний город.
6. Нажмите «🔄 Обновить» дважды подряд — второй раз бот сообщит, что данные
   обновлялись меньше минуты назад.
7. `/setcity`, затем `/cancel` — ввод отменён; следующее сообщение не ищется как город.
8. Проверка сбоя: при открытом прогнозе отключите VPN/сеть и нажмите «🔄 Обновить»
   через минуту — бот покажет сохранённый прогноз с пометкой и временем получения
   (ответ может занять до 15 с). Остальные разделы при этом работают.

### Известные ограничения погоды

- Кэш хранится в памяти: после перезапуска бота сохранённых данных для аварийного
  показа нет до первого успешного запроса.
- Без доступа к Open-Meteo ответ «недоступен» приходит через время таймаута (до 15 с).
- Названия мест и регионов — такие, как их возвращает геокодер Open-Meteo; для
  небольших населённых пунктов регион или страна могут отсутствовать.
- Прогноз и погода — модельные данные Open-Meteo, а не наблюдения метеостанции.
- Если Telegram API недоступен (например, без VPN), бот не получает сообщения вовсе —
  модуль погоды на это не влияет.

```text
reminder_handlers.py    команды, диалоги и меню напоминаний, часовой пояс
reminder_schedule.py    разбор даты/времени, DST, расчёт следующего момента
reminder_scheduler.py   JobQueue: постановка, отправка, повторы, восстановление
reminder_store.py       SQL-операции напоминаний и user_settings
weather_handlers.py     команды и меню погоды, выбор города, фоновые запросы
weather_service.py      клиент Open-Meteo: HTTP, повторы, таймауты, кэш
weather_format.py       тексты погоды и прогноза, коды WMO, единицы
weather_store.py        SQL-операции user_locations
tests/test_database.py  тесты SQLite на временных файлах
tests/test_bot.py       тесты настоящей диспетчеризации PTB с поддельным транспортом
tests/test_notes_*.py   тесты заметок: SQLite и диалоги через PTB
tests/test_reminder*.py тесты напоминаний: расписание, SQLite, диалоги и JobQueue
tests/test_weather_*.py тесты погоды: поддельный Open-Meteo, кэш, ошибки, диалоги
requirements.txt        зависимости
assistant.db            создаётся при первом запуске, исключён из Git
```

Путь к `assistant.db` абсолютный и вычисляется от расположения `database.py`:
`/home/lovecatsnyou/Projects/personal_assistant_bot/assistant.db`. Он не зависит от
текущей папки терминала. Все таблицы и индекс создаются через `IF NOT EXISTS`;
инициализация не удаляет существующие строки. Автоматических миграций сторонней
схемы нет: старую БД с другой структурой нужно предварительно изучить отдельно.

`users`: Telegram ID, username, имя/фамилия, даты регистрации и обновления (UTC).
`tasks`: ID, владелец, название, статус выполнения, даты создания/выполнения (UTC).
`notes`: `id`, `user_id`, `title`, `content`, `created_at`, `updated_at` (UTC).
`user_settings`: `user_id`, `timezone`, даты создания и изменения.
`reminders`: `id`, `user_id`, `text`, исходные `local_date`, `local_time`, `fold`
и `timezone` расписания, `repeat` (`once`, `daily`, `weekly`, `monthly`,
`weekdays`, `hourly`), `repeat_days`, `next_run_utc`, `status` (`active`, `paused`,
`done`, `failed`), `version`, `created_at`, `updated_at`, `last_attempt_at`,
`last_sent_at`, `error_count`, `last_error` (только тип ошибки). Индексы:
`(user_id, id)` и `(status, next_run_utc)`.
`user_locations`: `user_id` (одна строка на пользователя), `city_name`, `country`,
`region`, `latitude`, `longitude`, `timezone` (пояс места, не связан с `user_settings`),
`geocoding_id`, `created_at`, `updated_at`.
Поиск выполняется в SQLite через функцию `fold_text` (Python `casefold`), поэтому
регистр кириллицы учитывается корректно; символы `%` и `_` ищутся буквально.

Таблицы `notes`, `user_settings`, `reminders` и `user_locations` добавляются в существующую БД при
запуске (`CREATE ... IF NOT EXISTS`), без изменения остальных таблиц. Если в БД уже
есть одна из них с другой структурой (например, от старой версии), бот не
запустится с сообщением об этом и ничего в ней не изменит — такую таблицу нужно
перенести вручную.
Включены внешние ключи. Соединения закрываются после каждой операции, изменения
выполняются в транзакциях, обращения к SQLite вынесены из цикла asyncio через
`asyncio.to_thread`.

Для резервной копии остановите бота и скопируйте `assistant.db` в безопасное место.
Не удаляйте БД при обновлении или повторном создании виртуального окружения.
Локальные БД, журналы SQLite, резервные копии, секреты и кэши исключены в `.gitignore`.

Новые модули можно подключать отдельными функциями регистрации обработчиков в
`build_application()`. Общая БД доступна через `application.bot_data["database"]`;
состояние задач находится в отдельном ключе `user_data["tasks_state"]`, заметок —
в `user_data["notes_state"]` (последний поисковый запрос — `notes_query`),
напоминаний — в `user_data["reminders_state"]`, погоды — в `user_data["weather_state"]`
(результаты поиска — `weather_choices`, показанные места — `weather_places`).
Клиент Open-Meteo — `application.bot_data["weather"]`.
`/cancel` и кнопка `home` («Главное меню») зарегистрированы в `main.py` как общие.

## Офлайн-проверки

Из папки проекта, после установки зависимостей:

```fish
.venv/bin/python -m compileall -q main.py database.py task_handlers.py note_handlers.py reminder_*.py weather_*.py tests
.venv/bin/python -c 'import main, database, task_handlers, note_handlers, reminder_handlers, reminder_schedule, reminder_scheduler, reminder_store, weather_handlers, weather_service, weather_format, weather_store; print("Импорты OK")'
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python -m pip check
```

Тестам не нужны интернет и настоящий токен: SQLite создаётся во временных папках,
Telegram HTTP-транспорт заменён локальным. Основная `assistant.db` не открывается.
Проверяются CRUD и принадлежность задач, повторная инициализация без потери данных,
SQL-параметры, границы страниц, команды и кнопки, отмена и подтверждение удаления,
изоляция состояния пользователей, ошибки SQLite и редактирования Telegram-сообщений.
Для заметок — создание, чтение, изменение, удаление, поиск на кириллице, изоляция
пользователей, шаги диалога и отмена, пагинация, устаревшие кнопки, длина сообщений
и совместная работа с задачами. Для напоминаний — правила повторения, короткие
месяцы и 29 февраля, DST в Берлине/Варшаве, длительный простой, права владельца,
шаги диалога, редактирование, отключение, удаление, устаревшие кнопки,
восстановление после перезапуска, просроченные уведомления, сетевые ошибки и
блокировка бота, совместимость разделов. Часы в тестах зафиксированы, задания
`JobQueue` выполняются напрямую, без ожидания. Для погоды Open-Meteo заменён
`httpx.MockTransport`: поиск (в т.ч. на русском и одноимённые города), сохранение и
изоляция города, текущая погода и прогноз, коды WMO, отсутствующие поля, единицы,
часовые пояса, длина сообщений, кэш и TTL, устаревшие данные при сбое и их отсутствие,
DNS-ошибка, ConnectTimeout, ReadTimeout, HTTP 429/500/503, некорректный JSON, общий
таймаут, объединение одинаковых запросов, устаревшие кнопки, отмена поиска,
совместимость с задачами, заметками и напоминаниями.

В ограниченной среде Codex служебные сокеты asyncio могут быть запрещены
(`Operation not permitted`), из-за чего обычный асинхронный запуск тестов зависает.
Для этой среды предусмотрен отдельный запуск с периодическим пробуждением
тестового цикла событий; код бота, SQLite и рабочие потоки остаются настоящими:

```fish
.venv/bin/python -m tests.run_offline
```

Проверено на Python 3.14, python-telegram-bot 22.8, APScheduler 3.11 и httpx 0.28: 203 теста
прошли в обоих режимах запуска; компиляция, импорты и `pip check` также прошли.

Для ручной проверки после запуска откройте личный чат, создайте задачу через `/add`,
отметьте её выполненной и удалите с подтверждением. Для заметок: «📝 Заметки» →
«Добавить заметку» → заголовок → текст; затем `/notes`, `/searchnotes` (попробуйте
запрос в другом регистре), изменение через карточку и удаление с подтверждением. Со вторым Telegram-аккаунтом
список должен быть независимым.

### Живая проверка напоминания (2–3 минуты)

1. Остановите старый процесс бота, запустите новый: `python main.py`. В журнале
   должно появиться `Восстановлено напоминаний: N`.
2. В Telegram: `/timezone Europe/Moscow` (или ваш пояс). Бот покажет текущее
   местное время — сверьте его с часами.
3. `/remind Тестовое напоминание` → «Сегодня» → время на 2–3 минуты позже
   показанного → «Без повторения» → «✅ Создать».
4. Дождитесь сообщения «⏰ Напоминание». В `/reminders` оно станет ✅.
5. Восстановление: создайте ещё одно напоминание на +3 минуты, остановите бота
   (Ctrl+C) до срабатывания и запустите снова после него — напоминание придёт один
   раз сразу после запуска.
6. Повторение: создайте «Каждый час» и проверьте в карточке, что «Ближайшее»
   сдвинулось на час после отправки. Затем отключите его кнопкой «⏸ Отключить».

### Известные ограничения напоминаний

- Доставка «как минимум один раз», не строго один: если процесс аварийно
  завершится после отправки, но до записи в SQLite, напоминание придёт повторно.
- Если удалить или изменить напоминание в ту же секунду, когда оно отправляется,
  уже начатая отправка завершится.
- Точность — секунды: `JobQueue` работает внутри процесса бота; пока бот выключен,
  уведомления не отправляются.
- Ошибка SQLite в момент отправки (например, длительная блокировка файла) снимает
  задание до следующего запуска бота; в журнал пишется тип ошибки.
- Перевод существующего напоминания в новый часовой пояс не автоматизирован.
- Незавершённый диалог хранится в памяти и сбрасывается при перезапуске. Офлайн-тесты не заменяют проверку соединения
с Telegram и действительности вашего токена.

Справочник API: [CallbackQuery в python-telegram-bot 22.8](https://docs.python-telegram-bot.org/en/v22.8/telegram.callbackquery.html).
